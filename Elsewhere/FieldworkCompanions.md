# Fieldwork Companions

Repository `FieldworkCompanions`, folder `Tests/Pickle/Source/`, built by
`dotnet build Tests/Pickle/Source/FieldworkCompanions.PickleSteps.csproj -c Release` into
`Tests/Pickle/Mod/Pickle/Assemblies/FieldworkCompanions.PickleSteps.dll` (committed, since the staging copies the folder verbatim).
Every phrase carries the mod's name (`Fieldwork Companions: ...`, `the Fieldwork Companions ...`), for the same reason as above.
Written 2026-09-21. **The *Played* notes below come from one partial WSL run** (English, 19 of 32 scenarios, then the game ended
without writing its report, cause unknown): what it reached passed or failed as stated, the rest has not run. A fix made after
that run is marked "not replayed".

### Small and generic, candidates to move if a second mod wants them

| File | Steps | What they do, and what to know before copying |
| --- | --- | --- |
| `FieldworkSteps.cs` | `Fieldwork Companions: {string} is an obedient {string} that follows {string} at work` | **A player's animal with a master and the follow-at-work box ticked, for any animal mod.** Generates the pawn kind for the player, trains obedience, and only THEN sets `playerSettings.Master`: the game's setter logs `Attempted to set master for non-obedient pawn` (a `Log.Error`, which fails a scenario) for a pawn that has not learned it. The first run hit exactly that. *Not replayed after the fix.* |
| `FieldworkSteps.cs` | `... {string} is a {string} that follows {string} at work but has not learned obedience` | The state the UI cannot produce, built by writing the private `master` field (the steps assembly publicises Assembly-CSharp), because the setter refuses. *Not reached.* |
| `FieldworkSteps.cs` | `... {string} has learned the {string} training`, `... {string} is bonded to {string}` | Complete a `TrainableDef` (here Odyssey's `Dig` and `Forage`: tag the scenario `@requires:Odyssey`); add a `Bond` relation. *Not reached.* |
| `FieldworkSteps.cs` | `... a {string} rock stands next to {string}`, `... a ripe {string} stands next to {string}`, `... a cow {string}, full of milk, stands next to {string}` | Spawn a mineable rock, a full-grown plant or a milkable cow beside a named colonist, on a free standable cell found with `CellFinder.TryFindRandomCellNear`. The cow's udder is filled by writing `CompHasGatherableBodyResource.fullness` (protected, publicised). *Not reached.* |
| `FieldworkSteps.cs` | `... {string} brings down the rock next to them`, `... harvests the plant next to them`, `... milks the cow next to them` | **Trigger a gesture without playing the walk**, at the call the job driver ends with: `Mineable.DestroyMined`, `Plant.PlantCollected`, `CompMilkable.Gathered`. Right for any mod that patches one of those three. For the plant, the `Harvest` job is really started first (a patch may read `CurJob`), and `PlantCollected` drops no yield itself, the driver does, so only a bonus appears. *Not reached.* |
| `FieldworkSteps.cs` | `Fieldwork Companions notes what the map holds of {string}`, `... the map gained at least {int} of the noted resource`, `... gained less than {int} ...` | **Tell an assisted yield from a plain one by size**: the sum of `stackCount` of a `ThingDef` across the map, before and after. Sound only when the mod's bonus is larger than anything the plain gesture can give, which the scenarios arrange with a settings preset. Thresholds come from vanilla defs and have not been observed. *Not reached.* |
| `FieldworkSteps.cs` | `... a bonus mark floats over {string}`, `... no bonus mark floats over {string}` | A `MoteText` starting with `+` within two cells of a pawn, read from `map.dynamicDrawManager.DrawThings`. Motes are drawn objects, not listed things, so `listerThings` does not find them. The `+` is this mod's. *Not reached.* |
| `FieldworkSteps.cs` | `... the camera looks at {string}`, `the saved game {string} holds nothing written by Fieldwork Companions` | Jump the camera to a pawn (for a capture of something that lives two seconds); search a written `.rws` for a type-name string, to back a "nothing is saved" claim. Search a type name, not the mod's display name: a save's header lists the mods loaded, by name, so the name would match (that is what the step assumes; not yet seen in a real save). *Not reached.* |
| `SettingsSteps.cs` | `I open the Fieldwork Companions settings dialog`, `Fieldwork Companions scrolls its settings window to the bottom` / `back to the top`, `the Fieldwork Companions settings page has scrolled down` | The first opens `Dialog_ModSettings` and waits on its own frames (same reason as SkillIcons'). The scroll writes the mod's **private** `scrollPosition`; the last asserts it is above zero afterwards and prints it with `viewHeight`, to tell "the page does not scroll" from "the step did nothing". Written after two captures came out identical and cut off the last two controls. Open: passed. Scroll: ran; the assertion is new and *has not run*. |
| `SettingsSteps.cs` | `Fieldwork Companions settings are written to disk`, `the Fieldwork Companions settings file records {string} as {string}`, `Fieldwork Companions reading its settings file back gives {string} as {string}` | Same round trip as SkillIcons' (`VerificationSteps.cs`), with two things paid for. **A float is written with round-trip digits: `0.4f` lands in the file as `0.400000006`**, so a text comparison fails and this one compares numbers. And the read-back goes through `LoadedModManager.ReadModSettings<T>` into a *fresh* object and leaves the live one alone, so the static property and the `Mod` base class's field cannot end up disagreeing. The text comparison failed on the float and was corrected, *not replayed*. Read-back *not reached*. |
| `SettingsSteps.cs` | `Fieldwork Companions setting {string} is set to {string}`, `... setting {string} reads {string}` | Set or read any public field of the mod's `ModSettings` by name, with `Convert.ChangeType` and the invariant culture. The field name is the only specific part. Reads passed; sets ran. |
| `SettingsSandbox.cs` | *(hooks, no step text)* | `[BeforeScenario]` / `[AfterScenario]` that snapshot the public fields of the live settings, put them back, and back up and restore the settings file, **without replacing the settings object**. Also resets the window's scroll position. Silent when the mod is not loaded, since Pickle plays its own samples in the same process and a hook that throws would fail all of them. Ran around every scenario played; that the file was restored was not checked. |
| `ShortcutSteps.cs` | `the Fieldwork Companions shortcut is hidden on a clean configuration`, `... reveals its shortcut, as a customization mod would`, `... hides its shortcut again`, `the Fieldwork Companions shortcut is (not) drawn in the bar`, `Fieldwork Companions activates its shortcut`, `Fieldwork Companions sees a settings dialog open for itself` | The mod's own side of the MainButtons contract without RIMMSQOL: moves `MainButtonDef.buttonVisible`, asks the def's `Worker.Visible` and `Worker.Disabled` (drawn *and* not greyed), activates the worker, and asks the open `Dialog_ModSettings` which mod it was built for (the first `Mod`-typed field, so a field rename does not break it). Same as SkillIcons' and Bill Autopilot's. **Prefer `RimmsqolSteps` for the RIMMSQOL side.** Passed. |
| `LanguageSteps.cs` | `every Fieldwork Companions text exists in the language this pass runs`, `Fieldwork Companions key {string} does not read as a raw key` | **Every Keyed key of a mod is present in the active language**: takes the keys starting with the mod's prefix from the *English* resources and asks `activeLanguage.HaveTextForKey`, so a key added to the mod without a French entry fails even if the suite never heard of it. It asserts a floor on the number of keys found, so a filter that matches nothing cannot pass. Only the prefix and the floor are specific. Passed (English pass). |
| `HookSteps.cs` | `Fieldwork Companions has patched {string}` | `Harmony.GetPatchInfo` on `Type.Member`, for the mod's own Harmony id (`FieldworkCompanionsMod.HarmonyId`). The same as Work Studio's; promoting either means passing the id. Passed. |
| `ScreenshotSteps.cs` | `Fieldwork Companions hides the interface around the windows on screen`, `... brings the interface back` | A third copy of SkillIcons' and Work Studio's screenshot-mode steps (windows kept, Pickle's own lowered by assembly name, restored by an explicit step and by an `[AfterScenario]`). Promote one of the existing ones, not this. Passed; captures produced. |

### Not done, and why

A scenario clicking the settings window's *reset* button is written `@wip` with `I click button "<translation key>"`. That is
probably wrong: Pickle records a button under its *label*, so the step that fits is `KeyedClick/`'s `I click button keyed {string}`,
and staging it means a pass that is not the bare one. Not yet changed.
